# Incident Recorder: Black Box (STM32 Embedded System)

Автономний бортовий реєстратор інцидентів та умов транспортування вантажів на базі мікроконтролера STM32 NUCLEO-F411RE (ARM Cortex-M4 @ 84 MHz).

Проєкт розробляється в межах курсу «Системне програмування вбудованих систем» (КПІ ім. Ігоря Сікорського).

---

## Апаратне забезпечення стенда

* **Мікроконтролер:** STM32 NUCLEO-F411RE (STM32F411RET6, 512 КБ Flash, 128 КБ SRAM).
* **Інерційний сенсор:** InvenSense MPU-6050 (6-DOF: 3-осьовий акселерометр + 3-осьовий гіроскоп, шина I2C1, адреса `0x68`).
* **Мультисенсорний модуль:** GY-89 (10-DOF на шині I2C1):
  * L3GD20 — прецизійний 3-осьовий гіроскоп кутової швидкості (адреса `0x6B`);
  * LSM303D — 3-осьовий акселерометр та магнітометр орієнтації (адреса `0x1D`);
  * BMP180 — барометричний датчик тиску та температури (адреса `0x77`).
* **Енергонезалежна пам'ять:** Winbond W25Q64JV (SPI Flash 64 Мбіт / 8 МБ, шина SPI2 Mode 0).
* **Модуль фотофіксації:** OmniVision OV7670 (шина конфігурації SCCB/I2C1 адреса `0x21` + паралельна 8-бітна шина даних D[7:0]).
* **Виконавчий запірний механізм:** сервопривід TowerPro SG92R (апаратний ШІМ 50 Гц на PA6, живлення 5V VBUS).
* **Резервний телеметричний лінк:** FTDI FT232RL USB-UART (USART1 115200 8N1 на PA9/PA10).

Детальна розпіновка, альтернативні функції (AF), розрахунки дерева тактування та бюджет живлення наведені у [docs/pinout.md](docs/pinout.md).

## Архітектура програмного забезпечення

Прошивку організовано за 4-рівневою шаруватою архітектурою (Layered Architecture) із забезпеченням інверсії залежностей:

1. **`firmware/Core/`:** апаратна ініціалізація та обробники переривань, згенеровані STM32CubeMX.
2. **`firmware/Platform/`:** апаратні адаптери шин над бібліотекою HAL (`bus_interfaces.h`, `platform_stm32.c/.h`). Єдиний авторський шар, що взаємодіє з драйверами ST.
3. **`firmware/Devices/`:** платформонезалежні C-драйвери пристроїв (`mpu6050`, `bmp180`, `w25q64`, `servo`, `ov7670`). Повністю ізольовані від HAL, працюють через структури абстрактних інтерфейсів.
4. **`firmware/App/`:** прикладна логіка реєстратора інцидентів, Self-Test Bring-Up та обробка тригерів аварій.

Детальний опис та UML Component Diagram наведено у [docs/architecture.md](docs/architecture.md).

## Інструкція зі збірки та тестування

Всі команди виконуються з кореня репозиторію через єдиний інтерфейс `make`:

<pre><code>
# 1. Автоматична перевірка правил архітектурних залежностей
make check-deps

# 2. Збірка та запуск хостових Unit-тестів (x86-64)
make test

# 3. Крос-компіляція бінарного образу прошивки мікроконтролера (ARM Cortex-M4)
make build
</code></pre>

Результуючий бінарний файл формується за шляхом: `firmware/build/firmware.bin`.
