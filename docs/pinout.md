## 3. Розрахунок параметрів тактування шин (Clock Tree Calculation)

* **Первинне тактування:** Внутрішній високостабільний RC-генератор HSI = 16 МГц *(RM0383, Section 6.2.2, с. 97)*.
* **Головний помножувач PLL (RM0383, Section 6.2.3, с. 97; Section 6.3.2, с. 105):**
  * Вхідна частота VCO: f_VCO_IN = f_HSI / PLLM = 16 МГц / 16 = 1.0 МГц
  * Вихідна частота VCO: f_VCO_OUT = f_VCO_IN * PLLN = 1.0 МГц * 336 = 336 МГц
  * Системна частота SYSCLK: f_SYSCLK = f_VCO_OUT / PLLP = 336 МГц / 4 = **84 МГц**
* **Шина AHB (HCLK):** Prescaler = 1 -> **84 МГц** (тактування ядра Cortex-M4 і портів GPIO, RM0383, с. 109).
* **Шина APB1 (PCLK1, Low Speed Peripheral):**
  * Prescaler = 2 -> f_APB1 = 84 / 2 = 42 МГц (максимум для STM32F411 становить 50 МГц, RM0383, с. 108).
  * Тактування таймерів APB1 (TIM3): оскільки подільник APB1 != 1, частота подвоюється -> f_TIMCLK = 42 МГц * 2 = 84 МГц *(RM0383, Section 6.2, с. 95; Section 6.3.21, с. 136)*.
* **Шина APB2 (PCLK2, High Speed Peripheral):**
  * Prescaler = 1 -> f_APB2 = 84 МГц (тактування USART1, RM0383, с. 108).

### Розрахунок інтерфейсів:
1. **Шина I2C1 (Standard Mode 100 кГц, RM0383, Section 18.6.8, с. 499):**
   * Період шини: T = 10 мкс, півперіод T_high = T_low = 5 мкс.
   * Значення регістра `CCR`:
     CCR = T_high / T_PCLK1 = 5 мкс / (1 / 42 МГц) = 5 мкс * 42 МГц = 210 (0x00D2)
   * Значення регістра `TRISE` (максимальний час наростання 1000 нс, RM0383, Section 18.6.9, с. 500):
     TRISE = (1000 нс * 42 МГц) + 1 = 42 + 1 = 43
2. **Шина SPI2 (Winbond W25Q64JV, RM0383, Section 20.5.1, с. 598):**
   * Джерело тактування: APB1 (42 МГц).
   * Подільник `SPI_BAUDRATEPRESCALER_2` (біти BR[2:0] = 000): f_SCK = 42 МГц / 2 = 21 МГц (відповідає ліміту W25Q64 до 133 МГц і гарантує стабільність сигналу на макетній платі).
3. **ШІМ-таймер сервоприводу TIM3 CH1 (SG92R, RM0383, Section 13.4.11–12, с. 364):**
   * Опорна частота таймера: 84 МГц.
   * Подільник переддільника `PSC = 83`:
     f_CNT = 84 МГц / (83 + 1) = 1.0 МГц (крок лічильника 1.0 мкс)
   * Період переповнення `ARR = 19999`:
     T_PWM = (19999 + 1) * 1.0 мкс = 20000 мкс = 20.0 мс (50 Гц)
   * Керування кутом (тривалість імпульсу CCR1):
     * `CCR1 = 1000` (1.0 мс -> 0°, засув розблоковано)
     * `CCR1 = 1500` (1.5 мс -> 90°, проміжний стан)
     * `CCR1 = 2000` (2.0 мс -> 180°, засув заблоковано / опломбовано)
4. **Тактування камери MCLK (PA8 MCO1, RM0383, Section 6.2.10, с. 100):**
   * Вихідний сигнал MCO1 налаштовано напряму від джерела HSI (Prescaler = 1, біти MCO1[1:0]=00, MCO1PRE[2:0]=000) -> стабільна меандрова частота **16 МГц**, що входить у допустимий робочий діапазон сенсора OV7670 (10–48 МГц).

## 4. Бюджет струму та живлення (Power Budget)

* **Допустиме навантаження лінії 3.3 В плати Nucleo:** Вбудований лінійний стабілізатор LDO LD39050PU33R забезпечує максимальний вихідний струм до **500 мА** *(UM1724, Section 7.5.4, с. 23)*.
* **Розрахунок споживання лінії 3.3 В у найгіршому випадку (Worst-Case Peak):**
  * MCU STM32F411RE (@84 МГц, активна периферія): 25.0 мА *(DS10314, с. 72)*
  * MPU-6050 (Active, гіроскоп + акселерометр): 3.9 мА *(PS-MPU-6000A, с. 14)*
  * GY-89 (L3GD20: 6.1 мА + LSM303D: 0.3 мА + BMP180: 0.03 мА): 6.43 мА *(DocID022116; DocID023312; BST-BMP180)*
  * W25Q64JV Flash (режим циклічного стирання блоку Sector Erase): 25.0 мА *(W25Q64JV DS, с. 61)*
  * OV7670 Camera (активне захоплення пікселів): 18.0 мА *(OV7670 DS, с. 5)*
  * FT232RL (активна передача даних по UART): 15.0 мА *(DS_FT232R, с. 15)*
  * **Сумарний піковий струм на лінії 3.3 В:**
    I_total = 25.0 + 3.9 + 6.43 + 25.0 + 18.0 + 15.0 = 93.33 мА
  * **Коефіцієнт запасу:**
    500 мА / 93.33 мА ≈ 5.35
    Лінія завантажена лише на 18.6% від номіналу стабілізатора.

* **Живлення силового навантаження (Сервопривід SG92R):**
  * Струм холостого ходу сервоприводу становить 100–250 мА, а пусковий струм і струм блокування ротора сягають **до 500 мА** *(SG92R DS, с. 1)*.
  * **Схемотехнічне рішення:** Підключення сервоприводу до лінії 3.3 В **суворо заборонено**, оскільки імпульсне просідання напруги призведе до перезавантаження MCU через вбудований детектор Brown-Out Reset (BOR, RM0383, Section 5.2.2, с. 74). Сервопривід живиться безпосередньо від піна **5V (USB VBUS)**, а лінія землі з'єднана зі спільною точкою GND схеми.

## 5. Розділ «Відхилені варіанти» (Rejected Design Alternatives)

Відповідно до вимог п. 4.1 методичних вказівок, наведено аналіз альтернативних схемотехнічних рішень, які розглядалися на етапі проектування та були відхилені:

### Варіант №1: Використання пінів PB6 (SCL) та PB7 (SDA) для шини I2C1
* *Суть варіанта:* Використання первинної пари виводів I2C1, які призначаються конфігуратором STM32CubeMX за замовчуванням.
* *Причина відхилення:*
  1. На платах Nucleo-64 виводи PB8 та PB9 підведені до стандартних конекторів Arduino D15/D14, мають чітке маркування на платі та розташовані поруч із шинами живлення.
  2. Вивід PB6 за замовчуванням з'єднаний із піном Arduino D10, який часто використовується іншими модулями як лінія Chip Select для SPI.
  3. Перепризначення I2C1 на PB8/PB9 розвантажило нижній ряд пінів порту B і запобігло паразитному перехрещенню сигнальних шлейфів над мікроконтролером.

### Варіант №2: Організація паралельної шини камери D[7:0] на розрізнених пінах портів A і B
* *Суть варіанта:* Підключення ліній даних камери D0–D7 до довільних вільних контактів (наприклад, PA0, PA1, PB4, PB5 тощо).
* *Причина відхилення:*
  1. Оскільки MCU STM32F411RE не має апаратного блоку DCMI, зчитування кадру реалізується програмно на частоті такту PCLK (~8–16 МГц).
  2. При використанні розрізнених пінів для збирання одного 8-бітного значення процесору довелося б зчитувати кілька регістрів `IDR`, виконувати побітові зсуви (`>>`, `<<`) та операції логічного `OR`. Це вимагає 15–20 машинних тактів на кожен байт і призводить до 100% завантаження ядра процесора та втрати пікселів.
  3. Виділення неперервної групи пінів **PC0–PC7** дозволяє виконати атомарне зчитування всього байта за **1 машинний такт**: `uint8_t pixel_byte = (uint8_t)(GPIOC->IDR & 0xFF)`.

### Варіант №3: Генерація тактування камери через канал ШІМ таймера TIM1 (PA8) замість MCO1
* *Суть варіанта:* Налаштування піна PA8 як каналу TIM1_CH1 у режимі PWM із коефіцієнтом заповнення 50% для генерації частоти 16 МГц.
* *Причина відхилення:*
  1. Робота розширеного таймера TIM1 на такій частоті блокує ресурси таймера, які можуть знадобитися для точного захоплення зовнішніх подій.
  2. Використання виділеного апаратного виводу **MCO1 (Master Clock Output 1, AF0, RM0383, Section 6.2.10, с. 100)** транслює частоту внутрішнього генератора HSI безпосередньо на вивід PA8 без залучення таймерів і без споживання додаткової динамічної потужності.
